# Ledgerly — خارطة استكمال المنتج

> هذه الوثيقة خطة تنفيذ واختبار وليست ادعاءً بأن الميزات المدرجة مكتملة. لا تستخدم بيانات عملاء حقيقية قبل اجتياز بوابات الإصدار في RELEASE_READINESS.md.

## ترتيب التنفيذ

### المرحلة 1 — تثبيت الأساس واختبارات الانحدار
- [ ] تشغيل npm ci وnpm audit وnpm test وnpm run build على commit الإصدار الحالي.
- [ ] بناء مثبت Windows من main، تثبيت نظيف، تشغيل، تحديث/إعادة تثبيت، وإلغاء تثبيت.
- [ ] اختبار فتح الخزنة المشفرة، كلمة مرور خاطئة، إعادة تشغيل التطبيق، مرفقات مشفرة، وتصدير/استعادة نسخة احتياطية.
- [ ] إصلاح أي فشل قبل الانتقال إلى الميزات التالية.

### المرحلة 2 — دورة التدقيق الأساسية
- [ ] قبول العميل والاستقلالية وتعارض المصالح وإقرار موثق.
- [ ] إنشاء المهمة: الفترة، النطاق، إطار التقرير، الفريق، الأتعاب، الساعات، التواريخ، حالة الاعتماد.
- [ ] التخطيط: الأهمية النسبية وأساسها، مخاطر التحريف، تأكيدات الإدارة، إجراءات الاستجابة، والربط بأوراق العمل.
- [ ] استيراد ميزان المراجعة والتحقق من المصدر والمجاميع والحركة والأرصدة والخرائط الحسابية.
- [ ] دفتر القيود: اختبارات مجتمع القيود، الفلاتر، توثيق سبب الاختبار، ومراجعة الاستثناءات دون وصفها تلقائيًا بالاحتيال.
- [ ] أوراق العمل: الهدف، المجتمع، العينة، الإجراء، الأدلة، النتائج، الاستنتاج، المُعدّ، المراجع، الملاحظات، الإصدارات، والإحالات المتبادلة.
- [ ] الأدلة: بيانات المصدر، المالك/المصدر، التاريخ، النوع، مرجع ورقة العمل، مرفق آمن، وبصمة مصدر عند توفرها.
- [ ] الملاحظات: المعيار، الحالة، السبب، الأثر، التوصية، استجابة الإدارة، المسؤول، الموعد، الحالة، والأدلة.
- [ ] الإقفال: قائمة إجراءات مفتوحة، مراجعة اكتمال الملف، أخطاء مصححة وغير مصححة، تأكيدات الإدارة، أحداث لاحقة، وموافقة الشريك.
- [ ] التقارير: مسودات قابلة للتحرير مع مصدر الأرقام، تنبيه للخرائط/الإفصاحات الناقصة، وعدم الادعاء بأن المسودة تقرير ISA/IFRS أو نموذج أردني معتمد دون مراجعة مهنية.

### المرحلة 3 — الخدمات المهنية المساندة
- [ ] أخذ العينات: عشوائية، منتظمة، وMUS مع حفظ بذرة/طريقة الاختيار والمجتمع والاستثناءات.
- [ ] المطابقة البنكية: ملفات البنك ودفتر الأستاذ، خرائط الأعمدة، المطابقات المقترحة، الفروقات، والتسوية دون ترحيل تلقائي.
- [ ] طلبات مستندات العميل: قائمة PBC، المالك، تاريخ الطلب، الموعد، الحالة، والأدلة المستلمة.
- [ ] تأكيدات خارجية: المستلم، الإرسال، الرد، الاستثناءات، والمتابعة مع عدم تزوير أو اعتبار رد غير موثق تأكيدًا.
- [ ] الوقت والأتعاب والفواتير: سجل واضح قابل للتصدير مع فصل بيانات المكتب عن ملفات العميل.
- [ ] العمل الميداني: ملاحظات وصور محلية مع تحذير بأن رسم التوقيع ليس توقيعًا إلكترونيًا موثقًا.
- [ ] استيراد UBL/JoFotara: قراءة محلية للحقول المحددة فقط؛ لا يُدعى اتصال أو قبول رسمي من النظام الوطني دون تكامل رسمي واختبار صلاحيات.

### المرحلة 4 — تعدد المستخدمين والسحابة
- [ ] نموذج تهديد وتحديد حدود بيانات المكتب والمهمة والمستخدم.
- [ ] سياسات RLS لكل جدول وStorage، واختبارات سلبية بين مكتبين لكل مسار REST/RPC/Edge Function.
- [ ] أدوار وصلاحيات: مالك المكتب، شريك، مدير مهمة، مدقق، مراجع، قارئ، ومدير نظام؛ أقل صلاحية لازمة.
- [ ] دعوات آمنة ذات صلاحية محدودة، انتهاء صلاحية، إلغاء، وتسجيل تدقيق؛ تظل معطلة حتى الاختبارات الحية.
- [ ] تصميم تشفير طرفي للمحتوى السحابي وتوزيع/استعادة مفاتيح المكتب وتدويرها؛ لا يُكتفى بتشفير النقل أو تخزين قاعدة البيانات.
- [ ] مزامنة متعارضة بوضوح: نسخ وإصدارات، كشف تعارضات، وعدم الكتابة فوق تعديلات المستخدم بصمت.
- [ ] سجل تدقيق خادمي append-only بهوية موثقة وطوابع زمنية موثوقة وحماية من الحذف/التعديل.
- [ ] رفع ملفات خارجي بعد فحص نوع المحتوى والحجم والبرمجيات الخبيثة والحجر وسياسة الاحتفاظ والحذف؛ لا يوجد بوابة رفع خارجية حتى الآن.
- [ ] خطة نسخ احتياطي واستعادة واختبارات فقد مفتاح وحذف واحتفاظ وتوافق إصدارات.
- [ ] لا تفتح المزامنة أو الرفع الخارجي حتى اعتماد نتائج مراجعة أمنية مستقلة.

### المرحلة 5 — الجودة والتجهيز التجاري
- [ ] اختبار عربي/إنجليزي واتجاه RTL والطباعة وWord/PDF والتواريخ والأرقام والدينار الأردني.
- [ ] اختبار قابلية الوصول ورسائل الخطأ والحالات الفارغة وتأكيد الإجراءات الخطرة.
- [ ] اختبارات وحدة وتكامل وE2E وبيانات اصطناعية لمكتبين على الأقل، مع منع أي تداخل.
- [ ] اختبار أداء على ملفات كبيرة ضمن حدود موثقة وقياس الذاكرة وزمن التحليل.
- [ ] مراجعة مهنية لمنهجية التدقيق والتقارير والمعايير الحالية، ومراجعة قانونية/خصوصية محلية واختبار اختراق مستقل.
- [ ] إعداد سياسة الخصوصية والاحتفاظ والحذف، اتفاقية المعالجة، شروط الاستخدام، الدعم، الإبلاغ عن الحوادث، وإدارة الثغرات.
- [ ] إصدار موقع وموقّع إن أمكن، manifest SHA-256، ملاحظات إصدار، سجل قيود معروفة، وخطة rollback.

## شروط الإغلاق
- لا تعتبر الميزة مكتملة لمجرد ظهور شاشة أو وجود عنصر في القائمة.
- كل ميزة تحتاج اختبار قبول واضحًا، اختبار صلاحيات عند التعامل مع البيانات، ورسالة خطأ وحالة فارغة.
- كل نتائج التحليل مؤشرات للفحص وليست دليل احتيال أو رأيًا تدقيقيًا تلقائيًا.
- لا تعتمد التقارير النهائية أو الرأي أو الامتثال القانوني تلقائيًا؛ القرار للمدقق المسؤول.
- لا تُغلق بوابات السحابة والأمان قبل إرفاق نتائج فعلية قابلة لإعادة التنفيذ.
